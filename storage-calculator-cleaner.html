3. How the App Works - Local Processing Only

3.1 Storage Usage

Storage totals (total, used, free, percentage) are read using Android-supported APIs: StorageManager, StorageStatsManager, StatFs. No fake data is generated. All calculations are performed on-device using binary units (1 KiB = 1024 bytes) with overflow-safe logic.

3.2 MediaStore Scanner

Images, videos, audio, and screenshots are queried via MediaStore only after you grant the relevant media permission. We use Android thumbnail APIs, never retain huge Bitmaps, and process files incrementally on Dispatchers.IO.

3.3 Folder Scanner (SAF)

When you choose "Scan a Folder", we launch Android's system folder picker (ACTION_OPEN_DOCUMENT_TREE). We only scan inside the tree you granted. We persist URI permissions only if Android allows and only to rescan that folder later if you request it. We never assume access outside your selected tree.

3.4 Duplicate Detector

Duplicate detection runs only on files the App is allowed to read. Efficient multi-stage algorithm:

  • Stage 1: Group files by size
  • Stage 2: Same-size candidates only
  • Stage 3: Fast partial hash where useful
  • Stage 4: SHA-256 verification using buffered streams (no full file loaded into memory)

All hashing runs on Dispatchers.IO. Duplicates are shown as groups with potential savings. One file is kept unselected by default. You must explicitly choose what to delete.

3.5 Deletion & Trash

The App never silently deletes anything. Flow: Scan → Show results → You select files → Show summary (e.g., "37 files, 4.82 GB") → System/user confirmation → Delete/Trash → Rescan → Show recovered space.

For MediaStore content, we use Android's supported delete/trash flows including user confirmation where Android requires it. For SAF files, we delete only inside locations you granted. Where supported, we prefer moving media to Android's trash rather than permanent deletion. We clearly explain if recovery is not possible after permanent deletion.

We do NOT attempt to clear another app's private files or private cache. We do NOT pretend Android provides access it does not.

4. Local Preferences Only - DataStore

We use AndroidX DataStore Preferences only for small user preferences stored locally on your device:

  • Theme (Light/Dark/System + Material You dynamic color)
  • Onboarding completed flag
  • Default file size filter (10MB, 50MB, etc.)
  • Show binary vs decimal storage units
  • Confirm-before-deletion setting

We do NOT use Room database to store scan results or maintain a database of your filenames unless there is a strong technical reason. Scan results remain in memory and are regenerated on next scan.

5. No Third-Party SDKs, No Ads, No Analytics

In the initial version, Storage Calculator & Cleaner contains:

  • NO Firebase
  • NO Supabase
  • NO Google Analytics, Facebook Analytics, or any analytics SDK
  • NO AdMob, no advertisements
  • NO crash-reporting SDK that sends data off-device
  • NO backend, no cloud, no remote database
  • NO INTERNET permission, so network requests are technically impossible

Because there is no internet access, no data can be uploaded anywhere even if the code attempted it — Android would block it.

6. System Storage Manager Integration

For operations the App cannot perform itself due to Android privacy rules (e.g., clearing other apps' cache, reviewing system files), we use Android-supported system intents such as ACTION_MANAGE_STORAGE. We explain: "Android protects app data and some system files. You can use Android's Storage Manager to review additional storage." We never imply we can clean protected data directly.

For cache cleanup, we may delete only our own cache directly and show its actual size before clearing. For broader device cache, we invoke only system flows with clear explanation, never automatically or silently clearing other apps' caches.

7. Data Retention & Deletion

Since all data is local:

  • Scan results are held in memory only while you view them and are discarded when you leave the screen or the App is closed.
  • Preferences in DataStore remain until you clear App data via Android Settings or use in-app reset.
  • Files you choose to delete are deleted via Android's APIs. If moved to trash, they follow Android's trash retention (typically 30 days in MediaStore trash). If permanently deleted, deletion is immediate and not recoverable by the App.

There is no online account to delete and no server-side data to request deletion of.

8. Data Security

We take reasonable steps to:

  • Minimize permissions and request them contextually with explanation
  • Perform all file hashing and scanning on-device on Dispatchers.IO
  • Never block main thread with disk I/O
  • Avoid retaining thumbnails/bitmaps longer than needed
  • Support cancellation when you leave a scan screen
  • Use AndroidX Security best practices for DataStore

Because the App has no internet, the attack surface for remote data exfiltration is zero. Your storage analysis never leaves your phone.
